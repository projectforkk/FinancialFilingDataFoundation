# P11-ISSUE-131 SEC Discovery Observation Trust Boundary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make SEC P7/P8 research-ready state impossible without an exact, persisted, cryptographically revalidated and slot-bound discovery observation.

**Architecture:** Add one deterministic verification path for `SecDiscoveryObservation` that validates its canonical hash, persisted source bytes, candidate fingerprint, slot identity, selected accession and `UNAMBIGUOUS` state. P7 and ingest/reuse use that path before declaring readiness; P8 reconstructs the observation from the local Registry and verifies the catalog, validation, package and Registry chain without network access.

**Tech Stack:** Python 3, dataclasses, SQLite Registry, JSON canonicalization, SHA-256, pytest.

**Spec:** `design/33-p11-post-acceptance-design-correction.md`, `development/179-p11-corrected-design-repair-plan.md`, and the P11-ISSUE-131 repair task supplied by the user.

## Review Focus

- Missing observation: P7, ingest and reuse must not become research-ready.
- Tampered observation: canonical SHA, source bytes, candidate fingerprint and Registry row must each fail closed.
- Wrong slot binding: CIK/company/period/year/accession mismatches must not pass.
- Legacy SEC catalog: ticker-only identity or missing discovery fields must not enter current P8 serving.
- Valid chain: one verified Registry observation plus matching package/artifacts must pass P7, ingest/catalog publication and P8 serving.
